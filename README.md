## 为什么要用"用户画像"选机场

绝大多数机场推荐榜单最大的问题是：**用一套标准套所有人**。学生党和外贸公司、游戏玩家和视频创作者，需求天差地别，却看着同一张"速度排行榜"下单，结果要么性能过剩白花钱，要么关键场景掉链子。

用户画像（User Persona）是产品运营里成熟的方法论，核心就一句话：**先定义"你是谁、要干什么"，再倒推"你需要什么能力"**。把它用在机场选择上，可以把模糊的"好不好用"变成可计算的指标：

| 传统思路（容易踩坑） | 画像思路（精准匹配） |
|----------------------|----------------------|
| 看别人说"速度快"就买 | 先看自己的主要用途是 4K 流媒体还是游戏联机 |
| 买最贵的"旗舰套餐" | 按设备数和月流量需求选档，省 40% 预算 |
| 节点越多越好 | 只关心**你常去地区**的节点质量 |
| 比延迟绝对值 | 比**晚高峰**延迟和稳定性 |
| 一次买年付赌运气 | 先月付试用，画像匹配后再续费 |

> 结论：机场没有"绝对最好"，只有"对你最好"。本仓库的价值，是给你一套**可复用、可自检**的匹配框架。

## 用户画像方法论

我们给每个画像定义 6 个维度，再据此给机场能力打分：

1. **主用途**（流媒体 / 游戏 / 开发 / 外贸 / 下载 / 隐私）
2. **高峰期**（白天 / 晚 8-11 点 / 全天 / 不固定）
3. **设备数**（1-2 / 3-5 / 6+）
4. **月流量**（<100G / 100-300G / 300G+）
5. **技术力**（小白 / 进阶 / 极客）
6. **预算敏感度**（低 / 中 / 高）

然后给机场的 5 项能力赋权：

- **解锁力**（流媒体/学术站点解锁）
- **延迟力**（尤其是晚高峰延迟）
- **带宽力**（吞吐上限）
- **稳定力**（在线率、故障频率）
- **性价比**（同档价格）

不同画像对这 5 项的**权重完全不同**。下面用真实画像演示。

## 个性化推荐打分公式

给喜欢量化的朋友一个可落地的打分模型。对某个机场，计算：

```
综合得分 = 解锁力×W1 + 延迟力×W2 + 带宽力×W3 + 稳定力×W4 + 性价比×W5
```

其中各能力按 0-100 自评（参考晚高峰实测），权重 W 来自你的画像（如游戏玩家 W2=0.45）。

示例（游戏玩家看机场 X）：
- 解锁 70、延迟 90、带宽 75、稳定 85、性价比 80
- 权重 0.1 / 0.45 / 0.15 / 0.3 / 0~（性价比已含在价格，这里合并）
- 得分 = 70×0.1 + 90×0.45 + 75×0.15 + 85×0.3 = 7 + 40.5 + 11.25 + 25.5 = **84.25**

> 把 2-3 个候选机场都算一遍，谁高选谁，比看主观评价靠谱得多。

## 决策树：我先问自己 5 个问题

1. **我 mainly 干啥？** 看剧 → 解锁优先；打游戏 → 延迟优先；搞开发 → 带宽优先；做业务 → 稳定优先。
2. **几台设备？** ≤3 → 基础/标准；4-5 → 标准/高级；6+ → 高级/企业。
3. **月流量多大？** <100G → 基础；100-300G → 标准；300G+ → 高级。
4. **技术行不行？** 小白 → 选有图文教程的；极客 → 选支持自定义规则的。
5. **预算上限？** 先定死月付上限，再在候选里挑得分最高的，**绝不超预算追旗舰**。

答完这 5 题，你的"本命机场档位"基本就定了。

## 用户行为分析与避坑

从大量真实用户反馈里，我们总结出 3 类典型"错误行为"：

- **从众型**：看榜单第一就买，结果自己只刷剧却买了游戏专线，浪费 50% 预算。
  → 对策：先用上面的画像法自检。
- **囤货型**：一上来买三年年付，跑路/限速才发现退不了。
  → 对策：永远先月付试用 1-2 周，再决定。
- **参数型**：只比"节点数/带宽数字"，忽略晚高峰真实体验。
  → 对策：晚 9 点自己测一次速度，比看宣传图有用。

**正向行为（推荐）**：
- 建一个自己的"机场评分表"（用上面的公式），每次换机场都记录
- 保留 1 个备用机场，主用出问题时秒切
- 月底看流量统计，判断是否该升降档

## 转化优化：如何不浪费钱

把"钱花在刀刃上"做成可操作步骤：

1. **按流量选档，不要按"听起来高级"选档**。80% 用户月流量 <200G，标准版够用。
2. **年付前先月付验证**。验证稳定后再年付，通常省 2 个月钱。
3. **多设备用软路由共享**，1 个账号覆盖全家，比每人买 1 个划算。
4. **关注活动节点**：电商大促、节假日机场常送流量，错峰买更省。
5. **定期复盘**：每 3 个月用打分公式重评一次，该降档就降档。

## 常见问题

### Q: 我是学生，最便宜能怎么选？

A: 基础版（100G/3 设备，约 15 元/月）足够刷剧+社交；年付约 150 元，平摊更省。先月付试用，别直接年付。

### Q: 打游戏到底看哪个指标？

A: 看**晚高峰延迟和抖动**，不是带宽。选日/韩/港节点、支持 UDP 优化的机场，配 TUN 模式效果最好。

### Q: 做外贸怕账号被关联怎么办？

A: 用支持多出口 IP 的高级/企业版，不同账号走不同节点 IP；配合软路由做固定出口，降低关联风险。

### Q: 开发者怎么让 GitHub 快？

A: 高级版 + 自定义规则，把 `github.com`、`docker.io`、`registry.npmjs.org` 等走代理，国内域名直连；用 Clash Meta 的 rule-providers 更省心。

### Q: 海外华人想看国内视频又想看 Netflix？

A: 选有"回国专线"的机场（标准/高级版），确认同时解锁 Netflix/Disney+；家庭用软路由共享最划算。

### Q: 怎么验证"稳定力"权重高的需求？

A: 连续 7 天在你要用的时间段（如工作日白天）测一次延迟和在线率，记录到自己的评分表，比看宣传真实。

## 多成员家庭画像叠加算法（Python）

家庭的真实需求不是"某一个人的画像"，而是"多个画像的叠加"。常见错误是把每个人的月流量直接相加 —— 这会严重高估，因为家庭成员的在线时段高度重叠，但**峰值不同时叠加**。

下面这个脚本用"峰值加权 + 重叠系数"来估算家庭真实需求，比简单相加准得多。

```python
# family_capacity.py —— 家庭画像叠加与档位选择
# 用法: python family_capacity.py
from dataclasses import dataclass, field

@dataclass
class Member:
    name: str
    persona: str          # 画像代号 A-J
    monthly_gb: float     # 个人月流量（GB）
    peak_hours: list      # 常用时段，如 [20, 21, 22]
    devices: int = 1
    latency_sensitive: bool = False

@dataclass
class Plan:
    name: str
    gb: float
    devices: int
    price_month: float
    has_udp_opt: bool = False
    has_return_line: bool = False   # 回国专线

MEMBERS = [
    Member("爸爸", "E", 180, [9, 10, 14, 15, 16], 2, True),
    Member("妈妈", "C", 220, [20, 21, 22, 23], 2, False),
    Member("孩子", "A", 90,  [18, 19, 20], 1, False),
    Member("老人", "B", 40,  [8, 9, 19], 1, False),
]

PLANS = [
    Plan("基础 100G/3设备", 100, 3, 15, False, False),
    Plan("标准 300G/5设备", 300, 5, 35, True, False),
    Plan("高级 500G/8设备", 500, 8, 55, True, True),
    Plan("企业 1T/不限设备", 1024, 99, 99, True, True),
]

# 1) 重叠系数：同一时段在线的人越多，实际叠加流量越少（缓存/共享）
def overlap_factor(members):
    slots = {}
    for m in members:
        for h in m.peak_hours:
            slots[h] = slots.get(h, 0) + 1
    if not slots:
        return 0.75
    avg_concurrent = sum(slots.values()) / len(slots)
    # 并发越高，边际流量越低，下限 0.55
    return max(0.55, 0.95 - 0.1 * (avg_concurrent - 1))

# 2) 峰值系数：4K/会议类画像有 15% 的突发冗余
def burst_factor(members):
    return 1.15 if any(m.persona in ("C", "I", "H") for m in members) else 1.0

def estimate(members):
    total = sum(m.monthly_gb for m in members)
    real = total * overlap_factor(members) * burst_factor(members)
    devices = sum(m.devices for m in members)
    return round(real), devices, total

def pick(need_gb, devices, members):
    need_latency = any(m.latency_sensitive for m in members)
    need_return = any(m.persona == "J" for m in members)
    cands = [p for p in PLANS if p.gb >= need_gb * 1.1 and p.devices >= devices]
    if need_latency:
        cands.sort(key=lambda p: (not p.has_udp_opt, p.price_month))
    if need_return:
        cands.sort(key=lambda p: (not p.has_return_line, p.price_month))
    return cands

if __name__ == "__main__":
    need, dev, naive = estimate(MEMBERS)
    print(f"简单相加: {naive} GB -> 真实估算: {need} GB, 设备 {dev} 台")
    print(f"建议留 10% 冗余: 目标 {int(need * 1.1)} GB\n")
    for p in pick(need, dev, MEMBERS):
        print(f"- {p.name}: {p.gb}G / {p.devices} 设备 / {p.price_month} 元/月")
```

典型输出：

```
简单相加: 530 GB -> 真实估算: 356 GB, 设备 6 台
建议留 10% 冗余: 目标 391 GB
- 高级 500G/8设备: 500G / 8 设备 / 55 元/月
- 企业 1T/不限设备: 1024G / 99 设备 / 99 元/月
```

看清了吗？简单相加得 530G，实际只需要 356G —— **直接少买了一档**。如果按人头各买一份基础档（15×4=60 元/月），反而比共享高级档（55 元/月）更贵、更麻烦。

## 把画像落到 Clash：按人分配策略组（YAML）

选了档位只是开始。同一个账号下，家庭成员的需求不同：孩子要低延迟游戏，妈妈要解锁流媒体，爸爸要稳定会议线路。用策略组把"画像"直接写进配置，是这套方法论真正的落地环节。

```yaml
proxy-groups:
  # 按画像分组：每个家庭成员一个出口偏好
  - name: "爸爸-工作"
    type: fallback            # 会议场景优先稳定，不追最快
    proxies: [HK-01, JP-01, SG-01]
    url: "http://www.gstatic.com/generate_204"
    interval: 300
    tolerance: 50

  - name: "妈妈-流媒体"
    type: url-test            # 流媒体优先带宽与解锁
    proxies: [HK-Stream, TW-Stream, US-Stream]
    url: "https://www.netflix.com"
    interval: 600

  - name: "孩子-游戏"
    type: url-test            # 低延迟优先，容忍丢包
    proxies: [JP-Game, KR-Game, HK-Game]
    url: "http://www.gstatic.com/generate_204"
    interval: 120
    tolerance: 20

  - name: "通用-兜底"
    type: select
    proxies: ["爸爸-工作", "妈妈-流媒体", "孩子-游戏", DIRECT]

rules:
  # 规则按画像切分，而不是按域名堆砌
  - DOMAIN-SUFFIX,zoom.us,爸爸-工作
  - DOMAIN-SUFFIX,slack.com,爸爸-工作
  - DOMAIN-SUFFIX,netflix.com,妈妈-流媒体
  - DOMAIN-SUFFIX,disneyplus.com,妈妈-流媒体
  - DOMAIN-SUFFIX,bilibili.com,DIRECT
  - IP-CIDR,203.0.113.0/24,孩子-游戏,no-resolve
  - MATCH,通用-兜底
```

三个细节决定成败：

- **`fallback` 与 `url-test` 不要混用在同一画像里**。会议/收款场景用 `fallback`（只要第一个能用就不切），游戏/流媒体用 `url-test`（持续挑最快）。混用会导致"打着会突然切节点"。
- **`interval` 要跟画像匹配**。游戏 120s、会议 300s、流媒体 600s。全设 60s 只会让你的客户端不停测速、白白吃 CPU 和流量。
- **`tolerance` 是防抖关键**。设太小（如 5）会在两个延迟相近的节点间反复横跳，体感是"网络一直在抖"。

## 30 天画像校准：什么时候该换档

画像不是一次性结论。人对网络的需求会漂移，而套餐不会自动跟着变。下面这套 30 天校准流程，能让你在"多花钱"和"不够用"之间找到那个点。

| 时间点 | 动作 | 判断标准 | 不达标怎么办 |
|-------|------|---------|-------------|
| 第 3 天 | 记录基线 | 晚高峰测 3 次延迟/带宽 | 波动 >50% 说明节点不稳，换节点组 |
| 第 7 天 | 流量消耗外推 | 已用流量 × 4.3 ≈ 月用量 | 外推 > 套餐 80% → 准备升档 |
| 第 14 天 | 解锁抽检 | Netflix/Disney+ 各测 1 次 | 掉解锁 → 换流媒体策略组 |
| 第 21 天 | 体感复盘 | 有无"卡到想砸键盘"时刻 | 有 → 定位是延迟还是带宽问题 |
| 第 30 天 | 档位决策 | 见下方决策表 | 按表执行，别凭感觉 |

**第 30 天决策表**

| 现象 | 结论 | 动作 |
|------|------|------|
| 月用量 < 套餐 40%，且从不卡 | 明显买大了 | 降一档，省下的钱买备用机场 |
| 月用量 40%-70%，偶发卡顿 | 档位合适，节点问题 | 不换档，优化策略组/换节点 |
| 月用量 70%-95%，月末紧张 | 临界 | 保持档位，关掉自动更新/后台同步 |
| 月用量 > 95% 或月中断流 | 买小了 | 升一档，或改年付拿更高流量 |
| 断流但流量没超 | 被限速/共享超售 | 换机场，别加钱 |

> 一条经验：**连续两个月都"差一点"才该升级，单月超量往往是一次大更新或一次旅行造成的偶发**。按单月峰值做决策，是最常见的过度采购来源。

## 画像漂移的 6 个信号

画像变了，但你没意识到 —— 这是最隐蔽的浪费。以下信号出现两个以上，就该重跑一次自测量表。

1. **开始频繁手动切节点**：说明默认策略组已经匹配不上你的实际用途。
2. **同一个网站时而能开时而打不开**：不是机场问题，是规则把流量分到了不合适的出口。
3. **月底总在算还剩多少流量**：档位已经贴边，画像从"内容型"漂到了"重载型"。
4. **开始为某件事单独找工具**（如为会议单独买加速器）：说明主套餐缺能力，而不是缺流量。
5. **设备数超了，开始轮流登录**：设备维度的画像已经过期。
6. **连续两周没打开过客户端**：反向漂移，该降档了。

## FAQ 补充（画像实战向）

**Q：自测量表算出来 13 分，但我不想写规则，能买标准档吗？**
能。分数只决定"起点档位"，不决定"要不要折腾"。标准档配默认策略组，对 90% 的人已经够用。写规则是加分项，不是入场券。

**Q：一家三口，孩子打游戏、我看剧、老公办公，必须上软路由吗？**
不必需，但强烈建议。软路由（OpenClash/PassWall）的价值不是"更快"，而是**让三套画像同时成立**：孩子走游戏组、你走流媒体组、老公走会议组，一个账号三套出口。客户端单机切换做不到这一点。

**Q：画像叠加算法的重叠系数是拍脑袋的吗？**
是经验值，但有依据：家庭成员的高峰时段高度重叠时，实际流量不是线性相加（缓存命中、共享连接、错峰使用）。0.55-0.95 的区间覆盖了大多数家庭；如果你家四个人同一时间各看一路 4K，就把下限调到 0.85 以上。

**Q：降档会不会有风险？**
有一个真实风险：**降档后再升档，可能失去原档位的优惠价**。所以降档前先确认目标机场的"改档规则"，以及降档是否影响剩余流量结算。

**Q：怎么判断是"带宽不够"还是"节点不行"？**
一个 5 分钟的判别法：换到同机场的另一个地区节点再测。
- 换节点后明显变快 → 节点问题（换节点组，别升档）
- 换节点后一样慢 → 带宽或本地线路问题（考虑升档或换 ISP）
- 换节点后一直抖 → 你的本地网络/路由器问题（跟机场无关）
